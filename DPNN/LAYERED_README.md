## 0. 结论速览

1. **几何切割可以完全去掉。** DAG 中每条边 `u→v`（`u ∈ Parents(v)`，即 v 插入那一刻的 Delaunay 邻居）对应“查询的最近点在 v 插入时从 u 换成 v”的区域

   `Q(u→v) = Cell(u; V_{t_v−1}) ∩ Cell(v; V_{t_v})`，

   它**恰好等于**只由 `Parents(v)` 决定的约 16 个平分半空间之交（定理 1）。于是“某个候选还要不要比较”就变成“几组这样的半空间之交是否非空”（定理 2），用一个 3D 小 LP 判定：不建 Voronoi 胞腔，不维护随时间收缩的区域，也不裁剪多面体。只需要原 DAG（父子表）加点坐标。
2. **一层 / 多层 / 全部层是同一个判据**，差别只是参与求交的边数：1 层就是论文的简化版；k 层 = 最近 k 次跳转；全部层 = 整条查询路径。所有版本对每组 100 万个查询的返回值都与原 DPNN **逐点相同**；Lucy 和 bunny 的全部 4×100 万个查询都做了暴力核对，0 错误。
3. **比较次数**（2×包围盒内均匀查询，与论文同设置）：

   | 数据 | 插入顺序 | 原始(0层) | 1层 | 2层 | 3层 | 全部层 |
   |---|---|---|---|---|---|---|
   | bunny 73K | random | 157.2（论文 Ours1: 166.7） | 93.6（论文 Ours1*: 97.5） | 70.7 | 60.8 | – |
   | bunny 73K | FPS | 135.6（论文 Ours2: 135.8） | 73.1（论文 Ours2*: 74.1） | 56.3 | 51.3 | – |
   | bunny 73K | BRIO（仓库默认） | 184.1 | 112.9 | 83.8 | 70.7 | **57.2** |
   | uniform 20K | BRIO | 144.9 | 91.6 | 67.5 | 55.5 | **44.1** |
   | Lucy 1.02M | BRIO | 332.9 | 162.1 | 111.4 | – | – |
   | Lucy 1.02M | FPS | 236.3（论文 Ours2: 235.1） | 105.4（论文 Ours2*: 106.3） | 79.3 | – | – |

   1 层的结果与论文 Table V（他们用几何切割做的是同一件事）一致；层数继续加，比较次数还会下降，k = 5 时已在全部层极限的 7% 以内。
4. **纯组合判据不够**：最自然的“只看 Delaunay 邻接”规则是：从 a 跳到 b 后，只保留同时也是 a 的 Delaunay 邻居的候选 c。它会漏掉 15–16% 的必要候选，使 59%（uniform）/ 83%（bunny）的查询答案出错（§4）。所以坐标谓词省不掉；本实现把它压缩到最小形式：对 Delaunay 边的平分面做 LP。
5. **全部层的复杂度**（§5）：状态就是所有中间 Voronoi 图 V_1…V_n 叠加（overlay）后的胞腔。均匀体数据上约为线性，但常数很大（每点约 800–1000 个状态）；曲面数据实测 ≈ 120·n·ln n（bunny 73K：每点 1345 个，全部层表 5.8 GB，48 线程构建 87 s）。查询仍是 Θ(log n)（跳转次数 ≈ H_n 不会变），常数从约 14·H_n 降到约 4.7·H_n，也就是说，所有历史信息最多换来约 3 倍的比较次数下降。
6. **比较次数少 ≠ 查询快**，论文也观察到了这一点。DPNN 查询是一条依赖访存链，每次跳转至少一次 cache miss，比较本身几乎被延迟掩盖掉。精炼列表要配上“内联坐标的扁平布局 + 批量交错查询 + 大页”，比较次数的下降才变成实际加速（§6）：
   * bunny：0.77 → 0.50 µs/查询（3 层，−35%）、0.47 µs（全部层，−38%）；近表面查询 0.83 → 0.51 µs（全部层，−38%）；
   * Lucy（BRIO，仓库默认顺序）：1.64 → 0.78 µs（2 层，−52%）；近表面查询 2.19 → 1.10 µs（2 层，−50%）；
   * Lucy 改用 FPS 顺序（跳转次数 15.2 → 8.2）：2 层 float 版批量 0.49 µs（近表面 0.60 µs），相对原版快 3.4–3.7 倍；1 层单查询 0.77 µs；
   * 只精炼前 n/16 个点（`--coarse 16`）：Lucy 3 层 0.84 µs，内存 2.0 GB（float 版 1.0 GB，0.89 µs），速度接近全量 2 层（7.3 GB）。

   **推荐配置**：FPS 顺序（若能接受约 3 倍的 DAG 构建时间）+ 1–2 层 + 扁平布局 + 批量查询；内存紧张时用 float 版，或者 `--coarse 16`。
7. **构建时间**（Lucy 1.02M 点，48 线程）：DAG 10 s（串行的 Delaunay 逐点插入，原版 dpnn.cpp 用不精确谓词约 8 s），1 层 10 s，2 层 23 s；`RefinedDPNN` 端到端（2 层 + 扁平表）46 s，峰值内存 15 GB。只精炼前 n/16 时 3 层合计 11 s。构建以 LP 为主（2 层共 7.1 亿次），并行加速比 28–33 倍（§7）。

8. **状态内的测试顺序（§8，新增）。** 一个状态内的结果区域两两不交（定理 3），所以测试可以按任意顺序做；只要 LP 判定只剩一个结果，就可以停。这样建成的 LP 认证决策树：
   * 1 层以上比较次数稳定少 17–30%，返回值与原 DPNN 逐点相同；
   * bunny box：FPS 3 层 51.3 → 40.3（2.5·log₂n）；BRIO 3 层 70.7 → 53.7，已低于全部层顺序扫描的 57.2；
   * Lucy：FPS 2 层 79.3 → 64.3，BRIO 2 层 111.4 → 84.8；
   * 但查询时间反而慢 1.3–2 倍：树上的测试只能串行，而时间主要由访存延迟决定。
   * 离下界：决策树拿到了"顺序扫描 → 神谕"之间约 40–50% 的空间。再往下，必须改为只证明最终答案、不逐步证明整条路径。

## 1. 论文 VI.E 的思想

记 p_1…p_n 为插入顺序，V_m 为前 m 个点的 Voronoi 图，Φ_m(q) 为 q 在前 m 个点中的最近点。原 DPNN 在“Φ 于时刻 t 变成 v”之后，只用到 `q ∈ Cell(v; V_m)`，所以 v 的查询表 L_v 里每个后来的邻居 w 都要比较一次。

查询路径其实还提供了更多信息：每从 u 跳到 v（时刻 t_v），就说明 `q ∈ Cell(u; V_{t_v−1}) ∩ Cell(v; V_{t_v})`。论文 Fig. 14 指出，完整信息是所有这些区域之交，并实现了只用最后一次跳转的“简化版”：比较次数从 Table I 的约 235 降到 Table V 的约 106（Lucy，FPS），但是

* 预处理要对 Voronoi 胞腔做**几何切割**，代价高；
* **查询时间反而变慢了**（作者推测是内存/缓存的原因）。

## 2. 关键观察：区域只由插入时的 Delaunay 邻居决定

**定理 1.** 设 `u ∈ Parents(v)`，且 v 的新胞腔从 u 的旧胞腔中拿走了一块有内点的区域（u、v 在 V_{t_v} 中共享一个面，Delaunay 一般位置下即二者相邻）。则

```
Q(u→v) := Cell(u; V_{t_v−1}) ∩ Cell(v; V_{t_v})
        = { x : |x−v| ≤ |x−u| }  ∩  ⋂_{c ∈ Parents(v), c≠u} { x : |x−u| ≤ |x−c| }          (*)
```

*证明.* 对 x ∈ Cell(u; V_{t_v−1})，x 属于 v 的新胞腔当且仅当 |x−v| ≤ |x−u|，所以 Q(u→v) = Cell(u; V_{t_v−1}) ∩ H，其中 H = {|x−v| ≤ |x−u|}。记 (*) 右边为 R；Parents(v) 中的点都比 v 早插入，所以 Q ⊆ R。反过来，设 x ∈ R \ Q，取 y ∈ Q ∩ int H，线段 yx ⊂ R。线段离开 Cell(u) 的那一点 z 在 int H 中（y 在 int H 内，x 在 H 内），并且越过 z 后被违反的只能是某个 c ∉ Parents(v) 的约束（Parents 的约束在 R 内都成立）。这时 z ∈ F(u,c) 且 |z−v| < |z−u| = |z−c|，于是 z 附近 c 的旧胞腔里的点也严格更靠近 v，即 v 从 c 那里抢走了有内点的区域，得 c ∈ Parents(v)，矛盾。∎

> (*) 里只出现 v 插入那一刻的邻居，也就是原 DAG 中 v 的父节点表；既不需要 u 当时的邻居，也不需要任何 Voronoi 顶点或外接球心。
>
> 唯一的例外是凸包上两个相距很远的点：它们的无界胞腔只在极远处相交。LP 被限制在 ±1000 倍对角线的盒子里，这类边的区域在盒内为空（uniform 20K 中 313800 条边里有 6 条），盒内的查询不会走这些边。

## 3. 一层 / k 层 / 全部层的精炼查询表

**定理 2.** 查询沿边 e_1, …, e_r 走到 v（即依次在各边的时刻跳转），当且仅当 `q ∈ Q(e_1) ∩ … ∩ Q(e_r) ∩ Cell(v; V_m)`。因此，v 的候选 w（边 v→w）需要比较，当且仅当

```
Q(e_1) ∩ … ∩ Q(e_r) ∩ Q(v→w) ≠ ∅                                                   (**)
```

*证明要点.* (⇒) 显然。(⇐) 若 x 属于所有 Q(e_i)，则 Φ_{t(e_i)−1}(x) 是 e_i 的起点、Φ_{t(e_i)}(x) 是终点；两次跳转之间，当前点在更晚的时刻仍是最近点，所以在中间所有时刻也是最近点，因此 x 的整条轨迹就是这条路径。对候选 w：q 在时刻 t_w 跳到 w，当且仅当 q ∈ Cell(v; V_{t_w−1}) ∩ {|x−w|<|x−v|} = Q(v→w)。∎

**为什么不需要切割**：v 的区域在 t_v 到 t_w−1 之间被很多后来的点不断“切小”，但 Q(v→w) ⊆ Cell(v; V_{t_w−1}) 已经包含了这些切割的全部效果。所以 (**) 里**只出现原始的、静态的 Q**，没有任何需要随时间维护的几何对象。

(**) 是约 16(r+1) 个半空间的 3D 可行性问题。用 Seidel LP（`lp3.h`）求解，期望 O(m)；同一状态的所有候选共享路径部分的约束，所以先解一次路径，再对每个候选只“续算”它自己的约 16 个半空间（`LP3::prepare / extend`）。

* **0 层**（原 DPNN）：状态 = 节点，列表 = L_v。
* **k 层**：状态 = 最近 k 条边（离根不足 k 条时取整条路径）。实现上，**k 层的状态就是 (k−1) 层列表里的一个条目**；k 层列表 = 对 (k−1) 层后缀状态的列表再用 k+1 条边做 (**) 过滤；跳到候选条目 π 之后，新状态就是 π 本身。所以各层的查询循环完全相同，只是换了一张表。1 层即论文的简化版。
* **全部层**：状态 = 整条路径（trie，按 BFS 编号，子节点 id = 条目位置 + 1）。候选先用 1 层列表预过滤，再对整条路径解 (**)。
* **只精炼粗层**（`makeHybrid`，`--coarse D`）：插入序号 < n/D 的节点用 k 层表，其余用 0 层表。这样做是合法的，因为 0 层表在任何历史下都正确；而比较次数在 log(插入时刻) 上大致均匀分布，所以只精炼前 1/16 的点，就能保留大部分节省（§7）。

**精确性**：每个半空间放宽 1e-6（归一化坐标，包围盒对角线 = 1），LP 内部容差也只会把“不可行”判成“可行”。因此被删掉的候选，在这个余量下都不可能赢下一次浮点距离比较，查询走的路径与原 DPNN 完全相同。实验中，所有层、所有布局对每个查询返回的点都与原 DPNN 相同；Lucy 和 bunny 的 box、near 两组各 100 万个查询全部做过暴力核对（`--check 1000000`），0 错误；`test_layered` 还在退化输入上做了暴力比对（极小 n、重复点、9³ 整数网格、共面、共线、球面点），全部通过。适用范围：离数据中心 1000 倍对角线以内的查询；更远的查询请用 0 层表。

**空路径**：如果一条路径自己的半空间就不可行，而且把放宽量加大 100 倍（1e-4）仍不可行，说明没有任何查询能走到这个状态，它的列表留空；只在 1e-6 下不可行、放宽 100 倍后可行的，按数值失败处理，保留全部候选。这种状态确实存在：dpnn.cpp 把前 4 个点连成完全图，在共面这类退化输入上，其中某些边的区域 Q(u→v) 本身就是空的。早先的实现把所有路径不可行都当作数值失败、保留全部候选，于是这些状态的所有后代也都“不可行 → 全保留”，全部层 trie 在随机共面点上约 1/3 的概率会指数膨胀（12 个随机种子里 4 个超过每点 3000 个状态；修正后都是每点 34–40 个）。查询结果不受影响，因为这些状态本来就走不到。

> 关于放宽量：最初用的是 1e-9，对一般位置的点足够。但在**完全退化**的输入上（例如所有点都在一个球面上，于是所有平分面都经过球心），LP 本身也是退化的，Seidel 投影中的双精度舍入会吃掉 1e-9 的余量：420 万个 2 层 LP 里有约 100 个被误判为不可行，表现为偶发的 1/3300 查询错误。放宽到 1e-7 或 1e-6 后误判全部消失，而在普通数据上只多 0.03–0.5% 的表项，比较次数的变化小于 0.1%。

## 4. 能不能连坐标都不看、只用 Delaunay 组合信息？

实验（`analyze_combinatorial`）：对所有 2 步路径 a→b→c，比较
精确判据 Q(a→b) ∩ Q(b→c) ≠ ∅ 与组合判据 “a ∈ Parents(c)”（c 插入时也与 a 相邻）：

| 数据 | 可实现的 2 步路径 | 组合判据保留 | 可实现但被组合判据丢掉 | 组合判据保留但不可实现 | 用组合判据过滤后的查询错误率 |
|---|---|---|---|---|---|
| uniform 20K | 24.5% | 28.1% | **14.9%**（占可实现的） | 25.9%（占保留的） | **59.2%** |
| bunny 73K | 23.1% | 26.6% | **16.4%** | 27.5% | **82.9%** |

两个方向的错误都大量存在。直观原因：两个不同时刻的 Voronoi 图叠加是一个度量对象（例如 V(P′) 与 V(P) 的叠加等价于以 (a+b)/2 为中心、权为 −|a−b|²/4 的幂图），不由 Delaunay 组合结构决定。所以坐标谓词省不掉；本实现把它压缩成“对 Delaunay 边的平分面做一次 LP”，这已经是最小的几何量。

## 5. 复杂度

记 d̄ = 平均 |Parents| ≈ 14–17（3D），H_n = Σ1/i ≈ ln n。以下“期望”都指随机插入顺序 + 有界密度采样。

### 5.1 原始 DPNN（0 层）
* 空间 d̄·n。查询期望比较次数 = Σ_j E[1 + deg_j(Φ_j(q))]/j ≈ (1+d̄)·H_n（向后分析），实测约 13–14·H_n。
* 跳转次数 = 轨迹长度 ≈ H_n，任何层数都不改变它。

### 5.2 k 层
* 状态数 |S_k| = (k−1) 层条目数 + 1；条目数 |E_k| = 可实现的 (k+1) 步路径数。每个状态的平均列表长 ρ_k 很快趋近 1：

  | uniform 20K | k=0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 全部 |
  |---|---|---|---|---|---|---|---|---|---|---|
  | 条目/点 | 15.7 | 61 | 142 | 251 | 372 | 493 | 605 | 701 | 779 | 984 |
  | 每状态列表长 | 15.7 | 3.91 | 2.32 | 1.76 | 1.48 | 1.33 | 1.23 | 1.16 | 1.11 | ≈1 |
  | 比较次数/查询 | 144.9 | 91.6 | 67.5 | 55.5 | 49.9 | 47.0 | 45.7 | 44.9 | 44.5 | 44.1 |

* 预处理：LP 次数 = Σ_{长度为 k 的状态} |后缀状态的 (k−1) 层列表|，每个 LP 约 (k+1)·d̄ 个半空间，Seidel 期望线性，所以第 k 层代价为 O(|E_{k−1}|·ρ_{k−1}·k·d̄)。Lucy（1M 点）1 层是 3.2 亿次 LP（平均 47 个半空间），48 线程 10 s；2 层 3.9 亿次，23 s（单线程每次 LP 约 1.1 / 2 µs）。
* 查询：比较次数随 k 单调下降并收敛到全部层的值（上表），仍是 Θ(log n)。

### 5.3 全部层
* **状态 = 所有中间 Voronoi 图 V_1, …, V_n 叠加（overlay）后的胞腔**（定理 2：同一轨迹 ⇔ 同一叠加胞腔）。trie 中时刻 j 新建的节点数 κ_j = overlay(V_1…V_{j−1}) 中与新胞腔 Cell(p_j;V_j) 相交的胞腔数。
* **体数据期望 O(n)（启发式论证）**：时刻 k 新建约 d̄ 个直径 Θ(k^{−1/3}) 的“历史 Voronoi 面”。它们穿过直径 Θ(j^{−1/3}) 的新胞腔的期望个数约为 Σ_{k<j} d̄·(k^{−2/3}j^{−1/3} + k^{−1/3}j^{−2/3} + 1/j) = O(d̄) = O(1)，所以 E[κ_j] = O(1)，trie 总大小 O(n)。但常数很大：

  | n | 2.5K | 5K | 10K | 20K | 40K | 73K |
  |---|---|---|---|---|---|---|
  | uniform：trie 状态/点 | 802 | 785 | 987 | 984 | 1007 | – |
  | bunny 子采样：trie 状态/点 | – | 1027 | 1127 | 1188 | 1253 | 1345 |
  | bunny：状态/点 ÷ ln n | – | 121 | 122 | 120 | 118 | 120 |
  | 最大深度（uniform / bunny） | 26 / – | 26 / 28 | 36 / 32 | 33 / 33 | 31 / 34 | – / 36 |

  均匀体数据基本是线性的（每点约 800–1000）。曲面数据则精确地按 ≈120·n·ln n 增长，即实测 O(n log n)。一个可能的解释是：曲面采样的 Voronoi 胞腔是垂直于曲面的细长“针”，所有历史面都会在中轴附近、以及凸包外的无界区域汇聚，那里相当于一个二维的叠加，带来 Σ1/k 型的对数因子；上面的 O(1) 论证只适用于有界密度的体数据。
  **退化或近退化输入上会指数爆炸**：729 个点的 9³ 整数网格，trie 在深度 10 左右就超过 500 万个状态（每点 7000+）。加 1e-6 的随机扰动也一样，因为几乎共球的点之间会产生大量真实存在的细小“碎片”区域，它们的组合随深度相乘。球面点同理（所有胞腔在球心相遇）。k 层表仍然有界，但也更大（网格上 3 层每点 420–760 个条目，随机数据是 250）。规则采样的 CAD 模型可能落在这一类里。随机的共面点不在此列（每点 34–40 个状态，见 §3“空路径”）。
  最坏情况（3D Delaunay 可有 Θ(n²) 条边）没有有用的多项式上界。
* **查询 Θ(log n)**：下界是跳转次数 H_n（以及信息论下界 log₂n ≈ 1.44 ln n），上界是原始的 (1+d̄)H_n。实测全部层约 4.2–4.9·H_n（均匀），原始约 12–14·H_n。也就是说，用上全部历史信息，比较次数也只能降一个常数倍（约 3 倍）。
* **预处理**：LP 次数 ≈ trie 节点数 × 每节点候选数（约 7），每个 LP 约 d̄·深度 个半空间。体数据期望 O(n log n) 次基本运算，曲面数据再多一个 log 因子；常数巨大：bunny 是 7.3 亿次 LP（平均 243 个半空间），48 线程 87 s，扁平表 5.8 GB（float 版 2.9 GB）。超过 10⁵ 个点就不现实了。
* **结论**：全部层是理论极限；实用的是 k = 1–3，或者“只精炼粗层”的混合版。

## 6. 查询效率：为什么比较次数少了反而可能更慢，以及怎么变快

DPNN 查询每次跳转都要先拿到新节点的列表（一次依赖访存），原布局还要再取候选坐标（第二次依赖访存）。几十到几百次比较彼此独立，会被乱序执行重叠掉；真正决定时间的是约 H_n 次跳转的依赖延迟（Lucy：15 次跳转，每次约 100 ns）。实测在原布局上只换成精炼列表（每条边加 4 字节位掩码），时间几乎不变甚至更慢：Lucy 1 层比较次数 333 → 162，时间 1.64 → 1.59 µs；近表面查询 2.19 → 2.78 µs。

做法：
1. **扁平布局**（`FlatIndex`）：每个状态的候选连续存成 `{x,y,z,next}`（32 B），`next` 直接是下一张表的偏移，末尾的终止条目存答案。这样每次跳转只有一次依赖访存。
2. **批量交错查询**（`queryBatch<16>`）：16 个查询轮流推进，每轮每个查询只扫一张表并预取下一张表，延迟被互相重叠。这时时间开始正比于扫描量，比较次数的减少就直接变成加速。
3. **透明大页**（`madvise(MADV_HUGEPAGE)`）：表有几百 MB 以上、随机访问时，能减少 TLB miss。
4. **float 版**（`FlatIndex16`，16 B/条目）：坐标相对包围盒中心存成 float，带严格误差界 η = √3·2⁻²³·R；只有两个距离之差小于 2η 时，才回到 double 坐标精确重算（Lucy 上平均每查询 0.03 次），结果与 double 版逐点相同，内存减半。

## 8. 状态内的测试顺序：LP 认证的决策树

前面各层都只决定"列表里留哪些候选"，列表内部仍按插入顺序逐个比较。这一节换一个角度：同一个状态里，测试的顺序本身能不能更聪明？

新增：
- `src/dpnn_dtree.h`：构建与查询；
- `src/bench_dtree.cpp`：比较次数、计时，逐个查询与顺序扫描比对，并做暴力验证；
- `src/analyze_decision.cpp`：比较次数拆分、熵、神谕下界。

复现：`../results/run_dtree.sh`，结果在 `../results/decision/`。

### 8.1 比较次数花在哪里

bunny，BRIO，box 查询 200 万个（`analyze_decision`）：

| 结构 | 比较次数 | 跳转 | 跳转前的失败测试 | 终点扫描 | Σ H(结果 \| 状态) |
|---|---|---|---|---|---|
| 0 层 | 184.1 | 12.3 | 149.1 | 22.7 | 32.8 |
| 1 层 | 112.9 | 12.3 | 89.1 | 11.5 | 25.3 |
| 2 层 | 83.8 | 12.3 | 64.5 | 7.1 | 21.7 |
| 3 层 | 70.7 | 12.3 | 53.3 | 5.1 | 19.8 |
| 全部层 | 57.2 | 12.3 | 42.3 | 2.6 | 17.2 |

- **大头是"跳转前的失败测试"**：一个状态里按插入顺序逐个试，往往要试好几个才遇到比当前点更近的那个。
- **每次测试的信息量很低**：H(结果 | 状态) 是每个状态"下一步去哪"的熵，沿路径加起来只有比较次数的 1/3–1/6，也就是每次测试平均只带来零点几比特信息。

### 8.2 定理 3：状态内的测试可以按任意顺序做

设状态 s 的历史区域为 K，当前点为 u，候选按插入顺序为 c_1..c_m。DPNN 的规则是"跳到第一个比 u 近的 c_i，没有就停"。记

```
R_i    = K ∩ Q(u→c_i)                      结果为"跳到 c_i"
R_none = K ∩ ⋂_i { |x−u| ≤ |x−c_i| }       结果为"停"
```

**定理 3.** 这些区域两两不交，并覆盖 K（边界除外）。

*证明.*
- **不交**：Q(u→c_j) ⊆ Cell(u; V_{t_j−1})，即凡比 c_j 早插入的候选都不比 u 近。所以 i < j 时，R_i 与 R_j 只能在边界上相交。
- **覆盖**：由定理 2，列表中有所有满足 Q(u→c) ∩ K ≠ ∅ 的候选。因此 K 中的点要么属于某个 R_i，要么所有候选都不比 u 近。∎

**推论.** 每个测试答案（"c_j 比 u 近"或"不近"）都是一个半空间。对任意一组答案，若 LP 判定"K ∩ 这些半空间"只与一个结果区域相交，那么它就是 DPNN 的结果。

**为什么顺序扫描在纯逻辑下已经最优，几何怎样帮忙**：
- 不看几何，要确定结果 i，就必须证明 c_1..c_{i−1} 都不比 u 近，每个都得测一次；顺序扫描恰好不浪费任何一次测试。
- 几何能省测试：在已知区域里，有些结果区域已经与它不相交，对应的候选就不用再测。例如测出 c_5 比 u 近以后，c_2 那块区域可能已被排除。判定"还剩哪些结果"仍然是定理 2 那种 3D LP，只用 Delaunay 父子关系加坐标，不做切割。

### 8.3 做法

每个状态建一棵二叉决策树：
- **节点**：测"c_j 比 u 近吗"，计一次比较。
- **选测**：对每个候选 j，用 LP 算出"近 / 不近"两个分支各剩几个可行结果（前瞻一步）。选使 E[log₂(剩余结果数)] 最小的 j；如果叶子要跳到的候选从没测过（要补算一次距离），这一项再加 1。期望按训练查询在该节点的答案比例加权，没有训练数据的节点按等权处理。
  - 训练查询与测量查询用不同的随机种子：box、near 各 100 万个。
- **叶子**：LP 判定只剩一个结果。所有半空间都放宽 kRelax = 1e-6（与 §3 相同），所以任何结果都不会被误判为不可能。查询走的路径和返回的点与原 DPNN 逐点相同。
- **退化与上限**：
  - 已知区域放宽 100 倍仍不可行，说明这里走不到，放一个"停"叶子（同 §3 的空路径规则）。
  - LP 数值失败，或内部节点超过 4·m，剩余部分改用顺序链：按插入顺序测剩下的候选，逻辑上总是正确的。
- **查询**：只保留"当前距离"和"最近一次成功测试的距离"（pending）。
  - 若结果 i 的候选在路径上被测成"更近"，它一定是最后一次成功的测试：之后能改变结果的只可能是更早的候选，而那会让结果不再是 i。所以跨到下一状态时，令当前距离 = pending，不必重算。
  - 若结果是几何推出来的、c_i 从没被测过，就用一个 FORCE 节点补算它的距离，同样计一次比较。
- **布局**：每个节点 32 字节 `{x, y, z, a, b}`，类型（TEST / FORCE / END）和"跨状态"标志编码在 a、b 的高位。单查询用条件选择代替分支；批量查询每轮让每个查询只前进一个节点，16 路交错。
- **选测准则对比**（均匀 20K，2 层，box）：

  | 选测准则 | 比较次数 |
  |---|---|
  | 顺序扫描 | 67.5 |
  | 只看训练样本的信息增益 | 58.8 |
  | LP 前瞻一步 | 47.2 |
  | LP 前瞻两步 | 47.0 |

  信息增益衡量的是"对结果有多不确定"，而精确算法需要的是"离证明完成还差多少"，所以必须让 LP 参与选测。

- **与 log₂n 的倍数**：bunny box 的最好结果从 3.2·log₂n（FPS 3 层）降到 2.5·log₂n（40.3）；Lucy 从 4.0·log₂n 降到 3.2·log₂n（64.3）。
- **表不变大**：很多候选因为能被推出而永远不用测，所以 2 层以上决策树表反而比顺序表小。
- **构建**：每个节点都要对每个候选做前瞻 LP，所以 LP 次数比建顺序层多一个数量级。以 Lucy BRIO 为例，建 1、2 层共 7.1 亿次，2 层决策树要 109 亿次。这批构建是在负载 150–220 的机器上测的，所以时间偏长：bunny 3 层 142 s，Lucy BRIO 2 层 1422 s，Lucy FPS 2 层 738 s。

### 8.5 离下界还有多远

bunny，box。"神谕"是指已知 q 之后，用 LP 证明每一步结果最少要几次测试（每个查询独立地贪心求最小证明，3000 个查询）。任何一棵决策树对每个查询走过的测试都是一个证明，所以神谕是决策树的下界。

| 顺序 | 结构 | 顺序扫描 | 决策树 | 神谕 | Σ H(结果 \| 状态) |
|---|---|---|---|---|---|
| BRIO | 1 层 | 112.9 | 84.5 | 39.5 | 24.7 |
| BRIO | 2 层 | 83.8 | 61.9 | 34.6 | 21.1 |
| BRIO | 3 层 | 70.7 | 53.7 | 32.1 | 19.2 |
| FPS | 1 层 | 73.1 | 52.4 | 29.7 | 19.7 |
| FPS | 2 层 | 56.3 | 42.9 | 25.6 | 17.3 |
| FPS | 3 层 | 51.3 | 40.3 | 24.0 | 16.5 |

参照：答案熵 H(answer) = 12.7，log₂n = 16.15。

- **决策树拿到了"顺序扫描 → 神谕"之间约 40–50% 的空间。** 剩下的部分是"事先不知道 q"的本质代价：对 q 很短的证明，往往要先测对几个特定的候选，树却必须在测试之前就选定测什么。
  - 前瞻两步几乎没有改进（47.2 → 47.0），说明问题不在选测的贪心程度。
  - 只看训练样本的估计（每个状态用样本建 ID3 树并交叉验证）在 2 层给出 53.0，比 LP 认证的 61.9 乐观。那是因为它允许"罕见情况暂不排除"，而精确算法不能。
- **这类方法的极限**：凡是"逐步证明 DPNN 路径"的精确方法，都不可能低于 Σ H(结果 | 状态)，也不可能低于神谕。再往下，就必须不再逐步证明整条路径，只证明最终答案；那需要另一种数据结构。

### 8.6 查询时间：决策树不提速

bunny，5 轮交错计时取最小值，测试期间机器负载 140–150，所以绝对值偏高，但同一轮内的相对快慢可比。单元格为 µs/查询，格式"单查询 / 批量"。

| 顺序 | 结构 | 查询 | 顺序扫描 | 决策树 |
|---|---|---|---|---|
| BRIO | 2 层 | box | 1.08 / 0.80 | 1.66 / 1.41 |
| BRIO | 3 层 | box | 1.98 / 1.04 | 2.26 / 1.39 |
| BRIO | 2 层 | near | 1.49 / 0.97 | 1.99 / 1.62 |
| FPS | 2 层 | box | 0.80 / 0.48 | 1.11 / 0.91 |
| FPS | 3 层 | box | 1.10 / 0.64 | 2.18 / 1.40 |
| FPS | 2 层 | near | 0.96 / 0.68 | 1.62 / 1.08 |

比较次数少 20–30%，时间反而慢 1.3–2 倍：
- 决策树的下一次测试取决于上一次的答案，所以一个查询内部只能串行：每个节点都要等距离算完、比较完，才知道下一步读哪里。
- 顺序扫描的各次测试互不依赖，CPU 可以并行流水地算，跳转时的分支也大多预测正确。
- 正如 §6 所说，查询时间主要由每次跳转的访存延迟决定，距离计算本身很便宜。少算几次距离，抵不过多出来的串行依赖。

**结论**：决策树是"比较次数"这一指标上的改进（即论文所用的计数口径），不是提速手段。追求时间时，仍推荐 §6 的扁平顺序表 + 批量查询。

### 8.7 附注：用距离的数值剪枝（不属于比较计数模型）

到当前点 u 的距离 r = |q−u| 已经算出。候选 c 要比 u 近，必须满足 |u−c| < 2r（三角不等式，即 Orchard 剪枝）。|u−c| 可以预存，于是不必计算 |q−c|，就能跳过一部分候选。

下表是顺序扫描中仍需计算的"到 q 的距离"次数（bunny，`results/decision/bunny_*_orchard.txt`）：

| 顺序 | 结构 | box：原来 → 剪枝后 | near：原来 → 剪枝后 |
|---|---|---|---|
| BRIO | 0 层 | 184.1 → 173.7 | 171.6 → 48.6 |
| BRIO | 3 层 | 70.7 → 68.3 | 75.3 → 35.1 |
| FPS | 0 层 | 135.7 → 127.2 | 121.7 → 29.1 |
| FPS | 3 层 | 51.3 → 49.0 | 49.1 → 21.2 |

- **box 查询几乎没用**：查询离曲面远，r 很大。
- **near 查询能省一半以上**：查询离最近点很近，大多数候选都满足 |u−c| ≥ 2r。
- **口径不同**：每个被跳过的候选仍需一次"预存距离 vs 2r"的标量比较，所以按论文的"比较次数"计数不变，只是"距离计算次数"下降。它用的是距离数值，不只是比较的正负号，因此不在本文"只用 Delaunay 信息、只做比较"的框架内，这里只作为附注。

在自己的代码里使用（最简单）：

```cpp
#include "dpnn_refined.h"
std::vector<dpl::Vec3> points = ...;
dpl::RefinedOptions opt;                 // 默认：BRIO 顺序、2 层、double 坐标
opt.order = dpl::InsertionOrder::Fps;    // 可选
opt.levels = 1;                          // 0 = 原 DPNN
opt.floatCoords = true;                  // 可选：内存减半，结果不变
opt.coarseDivisor = 16;                  // 可选：只精炼前 n/16 个点
dpl::RefinedDPNN nn(points, opt);
uint32_t i = nn.nearest(q);                          // 输入数组中的下标
nn.nearestBatch(Q.data(), Q.size(), out.data());     // 批量，更快
```

或直接使用底层接口：

```cpp
#include "dpnn_flat.h"
dpl::Dag g = dpl::buildDag(points, dpl::InsertionOrder::Fps);  // 或 Brio / Random
std::vector<dpl::LayerIndex> L{dpl::buildLevel0(g)};
L.push_back(dpl::buildNextLevel(g, L));                       // 1 层
L.push_back(dpl::buildNextLevel(g, L));                       // 2 层
dpl::FlatIndex idx(L[2], dpl::stateNodes(L, 2));              // 或 FlatIndex16(L[2], dpl::stateNodes(L, 2), g)
uint32_t id = g.origId[idx.query(q)];                         // 输入数组中的下标
idx.queryBatch<16>(Q.data(), Q.size(), out.data());           // 批量：out[i] 是 DAG 节点号，用 g.origId 映射
```
